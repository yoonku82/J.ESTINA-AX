# 매출 알림판 ERP 연결 규약

현재 프런트엔드는 가상 일별 매출로 작동합니다. 실제 J-ERP·재무 ERP의 API, 인증, 계정·품목·채널 매핑을 확인하거나 연결한 상태는 아닙니다. 아래 규약에 맞춘 **회사 서버의 조회 전용 중계 API**를 구현하면 같은 화면에 실적을 공급할 수 있습니다.

## 조회

```http
GET /api/erp/sales?year=2026
Accept: application/json
```

웹페이지와 같은 출처의 서버가 로그인 세션과 조회 권한을 확인한 뒤 ERP에 접근합니다. ERP 자격 증명은 서버에서만 보관합니다. 브라우저 코드·저장소·URL에 키나 비밀번호를 넣지 않습니다. 응답에 고객·직원 등의 개인 정보는 필요하지 않습니다.

```json
{
  "asOf": "2026-10-26T15:30:00+09:00",
  "records": [
    {
      "id": "2026-10-26-jewelry-online",
      "date": "2026-10-26",
      "product": "jewelry",
      "channel": "online",
      "sales": 15000000,
      "operatingProfit": null
    },
    {
      "id": "2026-10-26-bags-offline",
      "date": "2026-10-26",
      "product": "bags",
      "channel": "offline",
      "sales": 5000000,
      "operatingProfit": 450000
    }
  ]
}
```

- `asOf`: 시간대가 포함된 ISO 갱신 시각. 서버가 제공할 수 있는 **데이터의 기준 시각**이며 HTTP 요청 시각으로 임의 대체하지 않습니다.
- `date`: 한국 시간 기준 매출 인식일 `YYYY-MM-DD`. 선택 연도의 1월 1일부터 현재 제공 가능한 기준일까지 전체 스냅샷을 반환합니다. 거래별 또는 일·품목·채널별 집계 행 모두 가능하나 서로 중복 포함하지 않습니다.
- `id`: 스냅샷 내 중복되지 않는 안정적인 식별자. 수정·취소 시 동일 거래나 집계 범위가 중복 계산되지 않도록 서버가 일관성을 보장합니다.
- `product`: `jewelry`(주얼리), `bags`(핸드백), `romanson`(로만손).
- `channel`: `online`(온라인), `offline`(오프라인), `global`(글로벌). 실제 회사 채널·ERP 코드 대응은 담당 부서와 확정해야 합니다. 현재 코드는 회사의 세부 채널 구성을 추정하지 않습니다.
- `sales`: **원(KRW) 단위 정수**인 순매출. 할인·부가세·반품·환율·인식일 기준은 재무·영업 부서가 하나로 확정합니다. 환불·취소 조정은 음수로 표시할 수 있습니다.
- `operatingProfit`: 같은 기간·품목·채널 기준의 **원 단위 정수**, 또는 비용 미확정·미제공 시 `null`. 영업손실은 음수입니다. 매출만 ERP에 등록돼도 판관비 등이 확정되기 전에는 실시간 영업이익을 만들거나 추정하지 않습니다. 일별 이익을 제공할 수 없다면 `null`로 반환하고 향후 별도 월·분기 확정 자료 구조를 협의합니다.

API가 실패하거나 권한이 없으면 적절한 401/403/5xx를 반환해야 합니다. 로그인 HTML을 200으로 반환하지 않습니다. `Cache-Control: no-store`를 권장합니다.

## 집계와 갱신

`dist/sales-data.js`는 응답의 날짜·코드·금액·중복 ID를 검증하고 한국 기준일의 일간, 당월, 당분기, 연초 누적을 합산합니다. 화면은 원을 100,000,000으로 나누어 억원으로 표시합니다. 선택 날짜 이후와 다른 연도의 행은 집계에 포함하지 않습니다. 집계 내 일부 이익이 `null`이면 전체 이익도 `null`이며, 데이터가 없을 때도 이익을 0으로 만들지 않습니다.

정수 계산의 정확성을 위해 행별 금액뿐 아니라 **스냅샷 전체 매출 절댓값 합계**와 **제공된 영업이익 절댓값 합계** 각각이 JavaScript의 안전 정수 한도 `9,007,199,254,740,991`원 이하여야 합니다. 양수·음수 상계로 순합계가 작더라도 이 한도를 넘으면 응답을 거부합니다. 이를 통해 품목·채널·기간별 부분합과 계산 도중의 합계도 안전 정수 범위에 머무릅니다. 한도 검사는 덧셈 전에 수행합니다.

프런트엔드의 주기적 조회는 60초 간격 폴링입니다. ERP에 저장한 즉시 브라우저로 보내는 푸시 방식이 아니며, **ERP → 중계 서버의 반영 지연 + 최대 조회 간격**이 걸릴 수 있습니다. 조회 성공 시 스냅샷 전체를 교체하여 같은 행이 누적되지 않도록 합니다. 실패 시 마지막 성공 데이터와 그 기준 시각을 유지하고 실패 상태를 표시해야 합니다. 샘플을 ERP 실적으로 표시하거나 실패 후 샘플을 실제 데이터로 자동 대체하지 않습니다.

## 개발 모듈

`window.AXSales` 및 Node CommonJS로 다음을 제공합니다.

- `koreaDate()`: 한국 기준 오늘 날짜.
- `createDemoData(date?)`: 해당 연초부터 기준일까지 3개 품목 × 3개 채널의 결정적 일별 샘플 스냅샷.
- `validatePayload(payload)`: 정규화된 새 스냅샷을 반환하거나 설명 가능한 오류 발생.
- `summarize(records, {date, period, product, channel})`: `period`는 `day`, `month`, `quarter`, `ytd`; 필터 기본값은 `all`. 반환값은 `{sales, operatingProfit, recordCount, start, end}`입니다.
- `quarterly(records, {date, product, channel})`: 해당 연도 4개 분기의 합계를 반환합니다. 진행 분기는 기준일까지, 미래 분기는 `end: null`, `recordCount: 0`입니다.

권한, 최신성, 수치 대사, 취소·수정 전표, 미확정 이익, 0건 응답, 접속 실패를 검증한 후에만 실제 ERP 연결 완료로 표기합니다. 정적 Python 서버에는 이 API가 없으며 별도 서버 구축이 필요합니다.
